# 架构与设计取舍

## 问题

把一份「待清洗商品表」（一行一件商品，带原始品名与三级分类）变成「标准分类 + 标准属性」两件事都正确的表，
并按属性模板逐 cell 落库。

输入有四份权威资料：

| 资料 | 内容 | 本项目的用法 |
| --- | --- | --- |
| 02 品名分类汇总 | 品名 → 大类/中类/小类 + 6 位分类代码 | 分类的**唯一来源** |
| 03 品名属性表 | 品名 → 属性名/类型/是否必填/字段类型/单位/枚举值 | 属性模板与校验规则 |
| 1-4 级完整最终对照表 | 人工复核后的四级路径（与 02 表存在冲突） | 口径对照 + 冲突登记 |
| 商品表本身 | 标题 / 品牌 / 制造商型号 / 销售单位 | 属性抽取的**唯一证据来源** |

## 分层

```
L0 数据契约   ingest / normalize / align        Excel 与 JSONL 双通道，按「原表行号」逐字校验
L1 本体层     ontology                        三张表 → 可查询索引 + 冲突登记
L2 推断层     classify / extract / graph-fill  分类判定 / 模板抽取 / 图谱传播与上下文推断
L3 交付层     emit / confidence-tiers          三张交付表 + 置信度分层
L4 验收层     annotate / precision-check       双盲标注与精度代理
```

## 四条硬规则

1. **分类来自表，不来自模型**：品名 → 02 表路径是恒等映射；模型只对"输入品名是否放错第 4 级"提供证据，且必须进复核队列。
2. **属性必须有模板**：模板外的属性一律不输出；枚举只能取候选值；数值必须可解析。三条让"幻觉属性"在结构上不可能出现。
3. **缺失是合法终态**：读不出就留空并进复核队列，绝不用同义词或常识补位；补位必须走独立的、可度量的推断通道。
4. **结构化列永远优先**：`产品名称 / 商品名称 / 品牌 / 制造商型号 / 型号 / 销售单位` 六项不接受任何推断改写。

## 为什么不做「Leiden 自动发现品类社区」

- 分类层级是业务给定事实（10 大类 / 93 中类 / 582 小类 / 7,201 条四级路径），聚类只能复现它，不产生新信息。
- 实测：把「同小类」当作社区边做候选扩展，在强索引上只带来 +3.8 pp 召回，候选集却从 10 涨到 29。
- 图里更值得建的是 **同物异名边**（插线板/接线板/排插 → 插座）和 **同型号边**（同一件货的不同包装），
  这两类边才带来新信息，而且都能用留一法验证。

## 推断补全的三层（逐层验证后才启用）

| 层 | 边 / 上下文 | 留一法精度 | 本次产出 |
| --- | --- | --- | --- |
| 同型号传播 | 同品名 + 归一型号完全相同 | 见 docs/findings.md | 3 cell（样本内型号几乎不重复） |
| 图谱上下文 | 品名文档 + 同品名已知取值分布 + 型号级判断 | 93.2% | 167 cell |
| 开放世界 | 允许型号公开规格知识，必须给依据 | 89.9% | 106 cell |
| 单条重试 | 逐条提问 + 同系列型号对照 | 89%（分属性 0.80–1.00） | 198 cell |

每层遵守同一组护栏：结构化属性不参与、枚举/数值强校验、必须给 `basis`、结果带置信度并进复核队列。

## 置信度分层

| 来源 | 置信度 |
| --- | --- |
| 结构化列 | 1.00 |
| LLM 模板抽取 | 0.99（200 行双盲实测 99.2%） |
| 图谱上下文推断 | 0.93–1.00（按组合留一法） |
| 单条重试推断 | 0.89（规格 0.80、芯片/页数 1.00） |
| 同型号传播 | 0.90 |

按 ≥0.95 门槛交付时必填覆盖率 84.7%，放宽到 ≥0.80 是 86.6%（见 docs/pipeline.md）。
