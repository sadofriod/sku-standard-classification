# SKU 标准分类与属性抽取

把一份「待清洗商品表」（一行一件商品）变成 **标准分类 + 标准属性** 两件事都正确的结构化数据：
分类来自权威目录表，属性按品名模板逐 cell 抽取，读不出的一律留空并进复核队列。

> 本项目基于某央企「办公设备及耗材」目录的 **1,000 条随机抽样**开发与验证。
> 仓库内只包含**合成样例数据**（`data/sample/`），不含任何客户数据。

---

## 一、我们怎么想的（思路）

### 1. 先量化，再设计

拿到数据第一件事不是建图、不是调模型，而是回答三个问题：

| 问题 | 实测答案 | 对设计的决定 |
| --- | --- | --- |
| 输入的分类和权威目录表一致吗？ | **1000/1000 完全一致** | "更正分类"不是重查三级分类，而是判断**第 4 级品名是否放错** |
| 两张权威表打架吗？ | 5 个品名、**441 行（44.1%）** | 口径必须做成显式配置（`--authority catalog\|reviewed`），代码不替业务拍板 |
| 属性有现成的吗？ | `属性参数` **1000/1000 为空** | 属性只能从标题抽；模板约束是唯一的幻觉防线 |

### 2. 明确谁说了算

- **分类以目录表为准**（品名 → 路径是恒等映射），模型只对"品名是否放错"提供证据，且必须进复核队列。
- **属性以模板为准**（03 品名属性表）：模板外的属性一律不输出，枚举只能取候选值，数值必须可解析。
- **结构化列永远优先**：`产品名称 / 商品名称 / 品牌 / 制造商型号 / 型号 / 销售单位` 六项不接受任何推断改写。

### 3. 缺失是合法终态

读不出就留空 + 进复核队列，**不用同义词或常识补位**。要补位，必须走独立的、能用留一法验证的推断通道：

| 推断通道 | 产量 | **命中率** | 预计错 |
| --- | --- | --- | --- |
| 同型号传播（同品名 + 同型号） | 3 cell | — | — |
| 图谱上下文（品名取值分布 + 型号级判断） | 167 cell | **99.7%** | 1 |
| 开放世界（允许型号公开规格，必须给依据） | 106 cell | **99.6%** | 0 |
| 单条重试（逐条 + 同系列对照） | 198 cell | **89.2%** | 21 |
| **推断合计** | **471 cell** | **95.3%** | **22** |

命中率 = 该（品名,属性）组合的留一法精度加权；推断值占已填必填 cell 的 9.3%，
因此整体必填错误率约 **0.4%**（22/5,088）。复现：`bun scripts/inference-hit-rate.ts`。

每个补出来的值都带 `依据` 与 `置信度`，并按门槛出表（≥0.95 → 必填覆盖 84.7%；≥0.80 → 86.6%）。
推断层的整体命中率 **95.3%**，其中图谱上下文与开放世界两层分别为 99.7% / 99.6%，单条重试层 89.2%。

### 4. 不用聚类"发现"品类社区

分类层级是业务给定事实（10 大类 / 93 中类 / 582 小类 / 7,201 条四级路径），聚类只能复现它。
实测把「同小类」当社区边做候选扩展只带来 +3.8 pp 召回，候选集却从 10 涨到 29。
真正值得建的边是 **同物异名边**（插线板/接线板/排插 → 插座）和 **同型号边**，因为这两类才带来新信息。

### 5. 没有真值就造一个可验证的

zip 里没有答案键，于是做**双盲标注**：200 行、两套提示词、独立两次，只认两次一致的结果。
结果：有值 cell 一致率 **92.2%**，生产结果与共识一致率 **99.2%**（7 处不一致全是粒度差异）。
这一步让"填了多少"变成了"填得对不对"。

## 二、结果（1,000 条实测）

| 指标 | 值 |
| --- | --- |
| 属性 cell 填充率 | 39.4%（纯规则）→ **55.5%**（含模型） |
| 必填覆盖率 | 61.2%（纯规则）→ 78.6%（模型）→ **86.6%**（含推断） |
| 按 ≥0.95 置信度交付 | **84.7%**，预计错值 16 个 |
| 关键属性覆盖 | **100%**（3000/3000） |
| 必填全满足的行 | 404 → **638 / 1000** |
| 枚举越界 / 数值非法 / 模板外属性 | **0 / 0 / 0** |
| 双盲精度代理 | **99.2%** |
| 推断命中率（471 个推断 cell） | **95.3%**（预计错 22，整体必填错误率 0.4%） |

成本：`deepseek-chat`，238 批 / 236,667 tokens / 77 秒（抽取层）。

## 三、跑起来

```bash
npm install                        # 运行时用 Bun ≥1.1
bun scripts/make-sample.ts data/sample          # 生成合成样例（已内置，可跳过）
bun src/pipeline.ts --data-root data/sample --out out --authority catalog   # 零 token 基线
bun src/llm/extract-llm.ts --data-root data/sample --out out-llm --batch 8  # 需要模型
bun src/emit-final.ts --data-root data/sample --llm out-llm/llm-rows.json --out out-final
bun scripts/confidence-tiers.ts --long out-final/属性明细_长表.csv --emit 0.95
```

`.env.example` 里是模型端点配置（任意 OpenAI 兼容端点）。完整链路与参数见 [docs/pipeline.md](docs/pipeline.md)。

## 七、已知边界

1. **必填覆盖 86.6% 是数据上限**：缺失 cell 里标题有证据的比例为 0（如硒鼓"总打印页数"缺 139 条，标题含"数字+页"的 0 条）。
2. **441 行口径冲突未裁决**：当前按 02 表输出，`--authority reviewed` 可一键重出。
3. **推断有置信度**：`graph_infer` 的值一律带依据并进复核队列，按门槛出表可把误差控制在 5% 以内。
4. **图谱层是可选组件**：社区摘要对"同物异名"有用，但对本任务的 cell 填充贡献为 0——真正起作用的是模板约束 + 型号知识。
